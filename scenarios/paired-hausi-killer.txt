# Hausi, TWO CLIENTS: the side wearing the trophy. The other half is paired-hausi-watcher, and its
# character wears nothing. Neither proves anything alone.
#
# The isolation rule is that the last blow decides, whoever owns the creature. A creature belongs to
# the machine that made it, so each round has one side spawn and the other strike:
#
#   Round 1: this side spawns, the watcher strikes. This machine runs the deaths and wears the trophy,
#   and must grant NOTHING, because the blow was not its own. Code reading the local slot passes every
#   single-player scenario and fails here. Trophies drop.
#   Round 2: the watcher spawns, this side strikes. The watcher's machine runs the deaths, wears
#   nothing, and must still grant the bonus and the block, read off this player's ZDO.
#
# Round 2's numbers are on the watcher's side, in its ledger.
#
# RUN WITH TrophyChance = 1 IN THE SERVER'S CFG and the default 0.25 on both clients. That is the
# differing-cfg case: Core imposes the host's value in memory, and a ratio of exactly 1.000 on a client
# can only come from the host's file. At 0.25 this file fails at that line.
